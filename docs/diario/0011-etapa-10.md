# Etapa 10 — O portão dos amigos

**Período:** 22/08/2026 · **Horas reais:** uma sessão longa com o Claude Code, do planejamento até o teste final · **estimado no plano:** ~31h / 3 semanas (revisado para ~30h depois de tirar um item do escopo — ver abaixo)

## O que eu queria com essa etapa

O jogo estava no ar desde a Etapa 9, mas só eu tinha jogado. Antes de mandar o link para amigos, seis coisas do `docs/backlog-pos-lancamento.md` (o documento que junta tudo que testar de verdade revelou, e que não estava no plano original) precisavam estar resolvidas: dava para jogar sem e-mail, tinha um teto pra não estourar a cota da API (compartilhada entre todo mundo que jogar), o feedback dos amigos tinha pra onde ir, o texto do mestre parava de mostrar asterisco cru na tela, e-mail confirmava de verdade antes de jogar, e o jogo não ficava visivelmente mais devagar do que era no meu computador.

## O que mudou

- **Convidado** (`POST /auth/convidado`): joga sem e-mail, o schema já permitia (`Usuario.email` é opcional desde a Etapa 8). `POST /auth/reivindicar` transforma o convidado numa conta de verdade sem perder os heróis — é um `UPDATE`, não uma conta nova. Um convite dispensável aparece no jogo depois do primeiro combate vencido ou 8 turnos, sugerindo criar conta.
- **Confirmação de e-mail bloqueante**: quem tem e-mail não consegue criar personagem nem jogar até confirmar (o link chega por e-mail via Resend, ou fica só no log do servidor se a chave não estiver configurada). Convidado e conta via Google não passam por isso — Google já confirma sozinho.
- **Teto de custo por usuário/dia**: 60 turnos para quem tem conta, 20 para convidado — contado pela tabela de telemetria que já existia (não por um contador em memória, porque a máquina do Fly desliga sozinha e um contador em memória zeraria a cada vez).
- **Botão "isso ficou estranho"**: o 👎 que já existia ganhou um campo de texto opcional.
- **Formato único da narração**: o mestre agora é instruído a não usar markdown, e o servidor limpa qualquer `**`/`#`/lista que escapar antes de guardar. Erro de turno, cura e morte de inimigo viraram cartões próprios (como os de ataque/teste já eram), em vez de texto solto com emoji dentro da narração.
- **Latência**: modelo de embedding baixado uma vez, na hora de montar a imagem do servidor, carregado no boot — não mais no primeiro pedido de um jogador. Migração do banco de dados saiu de "roda toda vez que a máquina liga" para "roda uma vez por versão publicada". A busca de memória parou de trazer a sessão inteira do banco a cada turno. A escrita de memória (que pode chamar o modelo de novo) passou a acontecer depois que o jogador já viu a resposta, não antes.
- `ADR-0016`, `Lição 11`, `docs/relatorios/0003-latencia.md`, este diário.

**O que saiu do escopo original:** a "gaveta mobile" (ficha do personagem virando um painel deslizante no celular) estava listada como pendente, mas o código já tinha isso pronto desde a Etapa 7 — o documento de backlog estava desatualizado. Achei isso rodando uma checagem no código antes de começar a planejar, em vez de confiar cegamente no que o documento dizia.

## O que quebrou no caminho

**A suíte inteira quebrou depois de ligar a confirmação de e-mail — e era esperado.** Testes de IDOR, de feedback, de telemetria: todos criam um usuário e tentam criar um personagem na sequência, e o personagem passou a exigir e-mail confirmado. A correção não foi desligar a checagem nos testes — foi fazer o usuário padrão da suíte (`conftest.py`) e o `_registrar()` de cada arquivo de teste já nascerem confirmados, porque nenhum desses testes é sobre o fluxo de confirmação em si. Só o arquivo novo (`test_confirmacao_email.py`) testa o caso não confirmado, de propósito.

**Uma coluna nova sem valor causa um `ALTER TABLE` que quebra em banco com dado.** A migration de `email_verificado` (booleana, obrigatória) falhou com "Cannot add a NOT NULL column with default value NULL" — o `default=False` do modelo Python só vale para quando o ORM cria uma linha nova, não para a coluna em si dentro do banco. Precisou de `server_default=sa.false()` na migration.

**O `python.exe` do computador virou vítima colateral de um conserto no Docker.** O Docker Desktop parou de subir com um erro de arquivo que ele mesmo cria e não consegue apagar — a causa era o Acesso Controlado a Pastas do Windows (uma proteção contra vírus de sequestro de arquivo) bloqueando o Docker de mexer numa pasta interna dele. Depois de liberar o Docker nessa lista, o `python.exe` do ambiente virtual do projeto (que não estava na lista) passou a ser bloqueado de criar pastas novas dentro do projeto — que vive dentro de uma pasta do OneDrive, protegida pelo mesmo mecanismo. `ruff`, `pytest` e o modelo de embedding, que cada um cria sua própria pasta de cache na primeira vez, pararam de funcionar até rodar sem cache ou apontando para uma pasta fora dessa árvore. Nada disso tem a ver com o código do jogo — é o sistema operacional protegendo a própria máquina, e valeu a pena registrar em detalhe na Lição 11 porque é exatamente o tipo de coisa que só aparece testando de verdade, nunca num teste automatizado.

**Duas sessões minhas trabalharam ao mesmo tempo na mesma pasta.** Enquanto eu fazia a Etapa 10, outra sessão minha estava adiantando parte da Etapa 11 (foto do personagem, música) no mesmo repositório. Descobri isso no meio de um teste no navegador, quando o clique parou de funcionar — o servidor de desenvolvimento estava recarregando por causa de um arquivo que eu não tinha tocado. Depois de confirmar que era mesmo outra sessão minha (não algo estranho acontecendo sozinho), passei a testar só com os comandos automatizados na maior parte do tempo, para não disputar o mesmo servidor.

## Decisões tomadas

- [ADR-0016](../adr/0016-convidado-e-confirmacao-de-email-bloqueante.md) — convidado sem tabela nova, e por que a confirmação de e-mail ficou mais rígida do que a primeira recomendação do backlog.
- [Lição 11](../../aprender/lessons/0011-onde-o-tempo-de-um-turno-vai.html) — como medir latência sem instalar nada novo, o padrão de "pagar o custo antes, não durante", e o caso do Acesso Controlado a Pastas.
- `docs/relatorios/0003-latencia.md` — os números reais (build, boot, e cinco turnos medidos contra a Groq).
- A-5 (gaveta mobile) saiu do escopo por já estar pronta — não foi decisão, foi constatação.

## Números

- 268 testes de backend passando no fim da etapa (eram 251 no começo desta etapa, dentro desta mesma sessão) — `ruff check` limpo.
- Build da imagem do Docker: modelo de embedding baixado em ~15s, uma vez. Boot do container: modelo carregado do cache em ~1,1s, sem baixar nada de novo — confirmado lendo o log do `docker run`, não só o código.
- Cinco turnos reais contra a Groq: busca de memória p50 58,8ms / p95 61ms; laço do agente (a chamada ao modelo em si) p50 2179ms / p95 5957ms — a chamada ao modelo domina o turno de longe, e isso não é coisa para essa etapa corrigir.
- Fluxo de convidado testado contra o backend real rodando (não só `pytest`): criar convidado → criar personagem → reivindicar conta → continuar acessando o mesmo herói.

## O que eu faria diferente

Rodar `grep` no código antes de aceitar qualquer item do backlog como "ainda não implementado" — a gaveta mobile já estava pronta, e só não caí nessa armadilha porque decidi checar antes de planejar. Vale virar hábito permanente, não só desta vez.

Também vale registrar: descobrir que outra sessão estava mexendo na mesma pasta ao vivo, no meio de um teste, foi mais desconfortável do que precisava ser. Se eu tivesse checado `git status` com mais atenção assim que notei o primeiro sinal estranho (em vez de continuar tentando debugar um clique que não funcionava), teria economizado algumas rodadas de investigação.

## O que ficou para depois

- **Deploy real em produção** — todos os números de latência desta etapa são de `localhost` e de `docker build`/`docker run` locais. O autor ainda não aprovou um deploy nesta sessão; os números de produção de verdade (com o Neon em vez do SQLite local, e o boot frio de uma máquina do Fly de verdade) ficam para quando isso acontecer.
- `min_machines_running = 1` no Fly.io — resolveria o resto do cold start, mas custa dinheiro por mês; decisão adiada de propósito, para depois de ver o quanto os quatro primeiros passos já resolveram.
- A lacuna de medição registrada no relatório 0003: a busca de regras (RAG sobre a bíblia) também calcula um embedding e não ficou dentro de nenhuma fase nomeada na instrumentação — o número está diluído entre as duas fases medidas, não perdido, mas uma rodada futura de medição deveria nomear essa fase também.
- Se o Acesso Controlado a Pastas continuar incomodando o dia a dia (fora desta sessão), vale adicionar `python.exe`/`uv.exe` à mesma lista de apps permitidos do Docker Desktop — não fiz essa mudança porque é configuração de segurança do Windows, fora do que uma sessão de código deveria alterar sozinha.
