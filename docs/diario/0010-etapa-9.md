# Etapa 9 — No ar

**Período:** 22/08/2026 · **Horas reais:** uma sessão longa com o Claude Code, verificando o estado das etapas anteriores, planejando com o usuário antes de mexer em qualquer coisa, e depois executando o deploy com testes ao vivo contra os serviços reais (Fly.io, Vercel, Neon, Langfuse, Groq) em cada passo · **estimado no plano:** ~20h / 2 semanas

## O que eu queria com essa etapa

Sair do `localhost`. Até aqui, "rodar o Mestre.IA" significava dois servidores na minha própria máquina — sem isso, ninguém além de mim consegue jogar, e não existe dado nenhum sobre custo, latência ou se o produto é bom o suficiente para alguém voltar. Esta etapa tinha três partes: infraestrutura de verdade (Postgres, Docker, deploy), instrumentação (Langfuse, telemetria de produto, feedback do jogador) e segurança (rate limit, sanitização, CORS restrito) — tudo isso para chegar num link público que não quebra no primeiro dia de tração.

## O que mudou

- **Backend no Fly.io** (`mestre-ia-backend.fly.dev`), **front na Vercel** (`mestre-ia-seven.vercel.app`), **Postgres no Neon** — as 6 migrations do Alembic (as 5 anteriores + a desta etapa) aplicaram limpo contra Postgres de verdade, sem nenhuma incompatibilidade de dialeto.
- **Proxy `/api/*` da Vercel para o Fly.io** (`Frontend/vercel.json`) — resolve um problema que não estava no plano original: o cookie de sessão (`SameSite=Lax`) não sobrevive a front e API em domínios diferentes de verdade. Ver ADR-0015 e Lição 10.
- **Rate limit por IP** (`app/infra/rate_limit.py`, `slowapi`) — 10/min em `/auth/login`/`/auth/registrar`, 20/min em `/chat`/`/chat/stream`.
- **Sanitização de input** — limites de tamanho em e-mail, senha, campos de personagem, mensagem de chat (nenhum tinha antes).
- **`SESSION_SECRET` trava em produção** — o backend recusa iniciar com o valor de dev se `ENVIRONMENT=production`.
- **Langfuse** — uma trace por turno (`app/infra/tracing.py`), com cada chamada real ao modelo como uma geração aninhada (o loop de ferramentas do ADR-0007 pode chamar o modelo várias vezes por turno), model/tokens/latência capturados no caminho síncrono; o caminho em streaming captura tudo exceto tokens (ver "o que quebrou").
- **Telemetria de produto** (`eventos_telemetria`) — sessão criada, turno jogado, personagem arquivado; `scripts/telemetria_resumo.py` calcula turnos por sessão, retenção D1/D7 e ponto de abandono por cima disso.
- **Feedback do jogador** (`feedback_narracoes`, 👍/👎) — o backend devolve o índice da narração em `historico_chat` (`turno_index`) a cada turno; o front anexa esse índice à bolha de texto quando o frame `state` chega, e dois botões pequenos (visíveis só depois disso) mandam o voto.
- `ADR-0015`, Lição 10, este diário, `docs/runbook.md`.

## O que quebrou no caminho

Nada disso apareceu em `pytest`/`ruff`/`mypy` — a suíte (215 testes no início da etapa, 222 no fim) continuou verde o tempo inteiro. Todos os itens abaixo só apareceram testando contra os serviços reais, ao vivo, antes de considerar cada fase pronta.

**`CORS_ORIGINS` como `list[str]` não sobrevive a uma linha de comando.** Pydantic-settings exige JSON estrito para preencher um campo de lista a partir de env var — passar isso pelo PowerShell (`fly secrets set 'CORS_ORIGINS=["https://..."]'`) chegou corrompido no servidor, e o backend crashava na inicialização com `SettingsError` antes até de tentar rodar a migration. Troquei o campo para uma string simples separada por vírgula.

**O Git Bash reescreveu `/api` como um caminho de arquivo Windows.** Configurar `VITE_API_URL=/api` na Vercel pelo Git Bash (MSYS) virou, sem erro nenhum visível, `C:/Program Files/Git/api` — o MSYS converte automaticamente qualquer argumento que pareça um caminho absoluto do Unix. Só apareceu porque o bundle gerado ainda continha `localhost:8000` (o fallback do código) em vez de `/api`. Corrigido com `MSYS_NO_PATHCONV=1`.

**Faltava uma regra de fallback de SPA no `vercel.json`.** Navegar direto para `/entrar` (não clicando de dentro do app) dava 404 — a Vercel não sabia que essa rota pertence ao React Router. Uma segunda regra de rewrite (`/(.*) → /index.html`) resolveu.

**`stream_options={"include_usage": true}` na chamada da Groq quebrava o streaming inteiro.** Pedi esse parâmetro (padrão em APIs compatíveis com OpenAI) para capturar tokens no streaming para o Langfuse — o SDK da Groq instalado não aceita esse parâmetro, e a chamada falhava com `TypeError`, derrubando o `/chat/stream` inteiro, não só a métrica que eu queria habilitar. Um teste ao vivo contra a API de verdade (não um mock) pegou isso antes do deploy. O streaming perde a contagem de tokens na trace; o resto continua.

**A chave certa do Langfuse, contra o host errado.** O Langfuse Cloud tem regiões separadas (EU/US) com hosts e chaves específicas por região. Usei o host padrão (EU) com uma chave de uma conta US — `401` silencioso no exportador de trace, sem derrubar o jogo (desenhado assim de propósito: tracing não deveria poder quebrar o produto). `Langfuse.auth_check()` revelou a região real da conta.

## O que eu faria diferente

Testar o cookie cross-site (a Fase D inteira) **antes** de escrever qualquer coisa das Fases E–H — o gap não estava no plano original (`PLANO_MESTRE.md` §Etapa 9 não menciona `SameSite` nenhuma vez), e só apareceu porque a verificação inicial leu o código de `routers/auth.py` com atenção antes de começar a implementar. Se essa leitura tivesse vindo depois, o login em produção simplesmente não funcionaria até o fim da etapa, e o retrabalho seria maior.

Também vale registrar, de novo: cada um dos cinco bugs desta etapa só apareceu testando contra o serviço real — nenhum apareceria com mais tempo gasto escrevendo teste automatizado. O tempo certo de gastar nisso é testar ao vivo cedo, uma fase de cada vez, não empilhar Fases B–J e só then testar tudo de uma vez no final.

## O que ficou para depois

- Domínio próprio — hoje só os subdomínios padrão (`*.fly.dev`, `*.vercel.app`), decisão deliberada (ver ADR-0015).
- `min_machines_running = 0` no Fly.io significa cold start no primeiro pedido depois de tráfego zero — aceitável na escala atual, documentado no runbook.
- Contagem de tokens no streaming não chega ao Langfuse (só no caminho síncrono) — o SDK da Groq não aceita `stream_options` (ver "o que quebrou"); revisar se uma versão futura do SDK passar a aceitar.
- Login com Google em produção — credenciais OAuth novas para o domínio público, adiado pelo usuário no começo desta etapa. O botão já é condicional; nada quebra por ficar de fora.
- Dívida de etapas anteriores, ainda pendente e fora do escopo desta etapa: calibração humana do juiz (Etapa 6), secret `GROQ_API_KEY` no CI (Etapa 6), confirmação visual da gaveta mobile em dispositivo real (Etapa 7).
